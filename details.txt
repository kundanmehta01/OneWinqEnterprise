 1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
OneWinq is an enterprise-grade platform for:
  - Digital identity & verified employee credentials
  - Smart NFC / physical card integration (tap -> live digital profile)
  - Employee networking (connections, real-time chat/messaging)
  - Enterprise events with RSVP + digital ticket passes
  - Public company branding & public employee profile pages (vanity slugs, QR)

It is a SINGLE-TENANT system: one organization (singleton CompanyProfile),
multiple employees, served through 4 distinct gateways:

  1) ADMIN CONSOLE        (/api/v1/admin/*)  - Executive management back-office
  2) EMPLOYEE PORTAL      (/api/v1/me/*)     - Personal workspace & experience
  3) NETWORKING/EVENTS    (/api/v1/network/*, /events/*, /user/*) - Social layer
  4) PUBLIC GATEWAY       (/api/v1/public/*) - Anonymous visitors + NFC taps

 7.6 REAL-TIME MESSAGING (Socket.IO)
   Handshake auth: JWT access token (handshake.auth.token or Bearer header);
   rejects suspended/inactive users; resolves member + singleton companyId
   On connect: auto-joins all active conversation rooms of the user
   Client events -> server: join_conversation, leave_conversation,
     send_message (text), delete_message, typing_start, typing_stop, mark_read
   Server -> room broadcasts: new_message, message_deleted, user_typing,
     user_stopped_typing, messages_read
   REST complement: file attachments (multipart, 10MB), paginated history,
     group/participant management, folders
   Rooms: `conversation:<id>`; io instance shared to controllers via app.set

 7.7 SECURITY SUMMARY
   - Argon2id (env-tunable memory/time/parallelism) + bcryptjs fallback
   - JWT: access 15m / refresh 7d, refresh rotation + FAMILY reuse detection
     (replay of a revoked token revokes the entire family = all sessions)
   - RBAC: requirePermission(...) per admin route; Super Admin bypass
   - Rate limiting: global (500 req/15min) + stricter auth limiter (10/15min)
   - Helmet security headers + CSP, CORS origin whitelist, credentials mode
   - Brute force: 5 failed logins -> 15-minute lockout (User.lockUntil)
   - Zod schema validation on inputs (validate middleware)
   - Audit logs auto-redact passwords/tokens/secrets
   - Client-side mirror: ProtectedRoute + permission guards + axios
     auto-logout on refresh failure (onewinq_auth_expired event)

 7.8 INTEGRATIONS (pluggable providers)
   EmailService  : Nodemailer SMTP | console | mock (env EMAIL_PROVIDER)
   StorageService: local disk (./uploads, statically served) | Cloudinary

 7.9 RESPONSE ENVELOPES

 9. KEY WORKFLOW DIAGRAMS
--------------------------------------------------------------------------------
 9.1 AUTHENTICATION & TOKEN ROTATION
   Login -----> verify argon2 hash -----> issue accessToken(15m) +
                                       refreshToken(7d, familyId #1)
   API call w/ expired access ---> 401 ---> axios interceptor queue --->
        POST /auth/refresh-token ---> new pair issued, old refresh revoked
        (queued requests replayed with new token)
   REPLAYED (already-revoked) refresh token detected
        ===> ENTIRE TOKEN FAMILY REVOKED (all sessions killed) + audit

 9.2 PROFILE APPROVAL LIFECYCLE
   Employee edits /app/my-profile  ->  saved to DRAFT only
        |
        v  POST /me/profile/submit
   calculateObjectDiff(published, draft) -> ProfileApproval record
   (diffSummary + draftSnapshot) ; draft LOCKED (isLocked=true) ;
   status=pending_review ; admins notified
        |
        v  Admin reviews at /admin/approvals
   +----------+------------+------------------+
   | APPROVE  | REJECT     | REQUEST CHANGES  |
   | copy     | status=    | status=          |
   | draft -> | rejected   | changes_requested|
   | published| unlock     | reviewer feedback |
   | status=  | notify     | unlock + notify   |
   | approved |            |                  |
   | unlock + |            |                  |
   | recompute|            |                  |
   | score +  |            |                  |
   | audit    |            |                  |
   +----------+------------+------------------+
   (Workflow only enforced when org setting requireApprovalForProfileChanges)

 9.3 SMART NFC CARD LIFECYCLE
   ADMIN SIDE                             PUBLIC SIDE
   add card stock (POST /admin/cards)     phone taps NFC chip
   status=unassigned                      GET /public/cards/:cardUid
        |                                      |
   link card (POST /admin/cards/link)     resolve by cardUid:
   bind memberId + profileId             - linked   -> tapCount++ ,
   status=linked                         |   lastTappedAt, CARD_TAP
        |                                |   telemetry -> { slug,
   [lost? blocked? reissue?]              |   redirectUrl /p/:slug }
   unlink -> status=unassigned            - unassigned -> activation
   (POST /admin/cards/unlink)             |   pending notice
                                         - blocked/lost -> security
                                             deactivation notice

 9.4 REAL-TIME CHAT FLOW
   User opens /app/messages -> messagingStore.connectSocket(accessToken)
   -> socket JWT handshake -> auto-join `conversation:<id>` rooms
   type text -> typing_start/stop -> opponent sees "typing..."
   send_message (socket, text) or REST (file attachment)
   -> io.to(room).emit('new_message') -> both UIs update live
   mark_read -> messages_read broadcast -> read receipts + unread badges

 9.5 EVENT RSVP FLOW
   Admin creates event (eligibility: all | departments | roles)
   -> employee GET /events (auto-filtered by own dept/role)
   -> POST /events/:id/register (capacity + deadline checks)
   -> ticket pass issued (OWQ-EVT-XXXXXX)
   -> visible in GET /events/my-events + UserEventsPage UI
